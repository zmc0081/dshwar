# 测量工具自身失效 —— 而它的读数与「被测对象坏了」一模一样

日期:2026-08-23(V0.9.0 Session 2)· 状态:约定 · 收录第四个实例

> **形状**:量东西的那个工具坏了,而它给出的读数**恰好像是被测对象坏了**。
> 于是人会去改被测对象 —— 那个本来是对的东西。
>
> 这一族与「守卫恒绿」相反:恒绿是**该报没报**,这一族是**报了,但报的是自己**。

## 实例 4:探针读的是注册那一刻的 state

`packages/design-system/test/checkbox-keyboard.tsx` 要观察两类事:

| 观察量                                              | 由什么驱动              |
| --------------------------------------------------- | ----------------------- |
| `onChange` 被调了几次                               | **React 状态**          |
| 焦点在哪、`:focus-visible` 命不命中、焦点环可不可见 | **DOM 状态**,不进 React |

第二类不触发重渲染,所以第一版给 document 挂了一组监听来刷新读数:

```tsx
useEffect(() => {
  const refresh = (what: string) => () =>
    window.setTimeout(() => setText(readDom(what, checked, toggles)), 0)
  //                                              ^^^^^^^^^^^^^^^^  ← 闭包捕获
  …
}, [checked, toggles])
```

`refresh` 捕获的是**注册那一刻**的 `checked` / `toggles`。
`setTimeout` 里的回调更把它推迟到下一拍。于是每次鼠标点击之后,
document 监听把读数刷成了**点击之前**的值 —— 而点击之前 `toggles` 就是 0。

### ⚠️ 读数长什么样

```
累计 onChange 次数       : 0
aria-checked             : false
```

**与「组件的 onClick 没有生效」完全一致。** 当时的下一步差点是去查
`Checkbox.tsx` 的 `onClick` —— 一段本来完全正确的代码。

真正拆开它的是一个不相干的动作:用 `b.click()` 程序化点击,
**隔一拍**再读 `aria-checked`,发现是 `"true"`。
即:**同步读得到 0,异步读得到 1** —— 那不是组件的行为,是观察时机的行为。

### 修法

把 React 状态的最新值放进一个**模块级快照**,监听读快照而不是闭包:

```ts
const latest = { checked: false, toggles: 0, label: '(初始)' }
// Harness 每渲染一次同步一份
latest.checked = checked
latest.toggles = toggles
```

监听的依赖数组随之清空(`[]`)—— 它不再依赖任何 state,
也就不再需要重注册,而重注册正是把旧值封进闭包的那条路径。

## 这四个实例的共同点,以及它给出的操作

四次都满足同一句话:

> **工具的失效模式,与被测对象的一种真实故障,在输出上不可分。**

于是:

### 判据:读到一个「被测对象坏了」的读数时,先证明工具是好的

具体到能做的动作 —— 挑一个**已知结果**的输入喂给工具,看它报不报对:

| 实例 | 怎么先证工具                                         |
| ---- | ---------------------------------------------------- |
| 1    | 给 `median` 一个非空数组,确认它算得对                |
| 2    | 拿一个**一定命中**的锚点跑一次,确认它真的改了文件    |
| 3    | 找一个**确实有**归档指针的版本块,确认它报「通过」    |
| 4    | **程序化触发一次**,绕开被怀疑的那条通路,看结果变不变 |

第 4 行是通用形态:**换一条与被怀疑对象无关的通路重测一次**。
两条通路结果一致 → 被测对象真的坏了;不一致 → 坏的是观察方式。

⚠️ 这与「凡改一处再看结果的验证,先断言那一处真的被改到了」是一对:
那条管**实验做没做成**,这条管**读数是不是工具自己的**。

### 顺带:探针里的「过期闭包」有一个具体的形状

**effect 里注册的长生命周期监听,捕获的是注册那一刻的 state。**
这在业务代码里通常表现为「界面显示的是旧数据」——刺眼,很快会被发现。
而在**探针**里,它表现为一个恒定的读数,
而恒定的读数看起来像「这个量确实没变」。

⇒ 探针要读**当下**,就不能读闭包。快照、ref、或者每次现取 DOM,三选一。
