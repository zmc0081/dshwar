# 决策:项目名 "DSHWAR"

> 日期:2026-08-15 · Session 8 · 状态:**待法务复核**
> 对应 `SESSION_TASKS.md` 的待确认项与 `KICKOFF.md` 第一节决定 5

## ⚠️ 本文件不是法律意见

作者不是律师。以下是**已做的降险措施**与**待复核的问题清单**,
供法务在发布前判断。`CLAUDE.md` 第九节要求「发布前过一次法务」——
**这一步尚未完成**。

## 名称构成

`DSHWAR` = `dsh` + `war`(如 warehouse / warden 的前缀感),读作 /diːʃwɑːr/。

- **不含 "DeepSeek"** —— 这是最重要的一条
- npm 作用域 `@dshwar/*`,与上游 `@deepseek-ai/*` 无视觉混淆
- 项目不使用上游的任何 logo、配色或视觉标识

## 风险评估

| #   | 风险                   | 判断       | 依据                                                            |
| --- | ---------------------- | ---------- | --------------------------------------------------------------- |
| 1   | 名称含上游商标         | **低**     | 不含 "DeepSeek"。`dsh` 是上游的 **CLI 命令名**,不是其品牌名     |
| 2   | 暗示官方关系           | **低**     | README 首屏与 LICENSE 双处声明非官方、无隶属、无背书、无赞助    |
| 3   | 指名性使用越界         | **低**     | 对上游名称的引用仅用于**识别所扩展的项目**,未用于修饰本项目自身 |
| 4   | `dsh` 本身被主张为商标 | **未确认** | 需要检索。三字母 CLI 名的显著性通常较弱,但非零                  |
| 5   | 与既有商标冲突         | **未检索** | "DSHWAR" 看起来是生造词,但需要在目标法域做正式检索              |

## 已做的降险措施

1. **README 首屏 + LICENSE 尾部**都有完整声明:非官方、无隶属、无背书、无赞助
2. 明确写出 "DeepSeek"、"DeepSeek Harness"、"dsh" **归各自权利人所有**
3. 明确本项目对上述名称的引用限于**指名性使用**
4. 不使用上游的 logo、配色、视觉标识
5. npm 作用域与上游明确区分

## 发布前必须完成

- [ ] **商标检索**:在目标法域检索 "DSHWAR" 与 "dsh"(风险 4、5)
- [ ] **律师复核**上述声明措辞是否足以支撑指名性使用抗辩
- [ ] 若需改名,**在有用户之前改** —— 有用户后改名成本陡增

## 为什么现在就记录而不是等法务

改名的成本随用户数陡增。把风险点、已做措施、待办事项在**第一次发布之前**
写清楚,是为了让法务复核变成一次半小时的确认,而不是一次考古。

结论若为「需要改名」,受影响的是:npm 作用域、仓库名、包名、
`adapters/` 目录名之外的全部文档 —— 代码逻辑零影响。
