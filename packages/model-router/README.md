# @dshwar/model-router

模型准入与预算降级。**裁决,不路由。**

> 本项目不是 DeepSeek 官方产品,与 DeepSeek 无隶属关系。

## 一句话边界

本包只在 `createAgent` 的**入口**回答「这个 principal 此刻允许用哪个模型」,
裁决完交回上游 —— 真正的模型调用、重试、流式全是 `dsh-llm` 的事。
名字里有 router,但它不碰任何请求(上游做能力,DSHWAR 做治理)。

## 准入是 opt-in 的治理

没配策略的租户**默认放行**。准入解决的是「试用用户不许调最贵的模型」这类
商业问题,不是安全问题 —— 默认封锁会让每个新租户先撞一次 403,然后运维学会
「上来先配个全通策略」,治理从此变成仪式。

清单外的请求 → **拒绝(403),不静默换**。空清单 = 全部允许(契约语义)。

## 降级是显式配置,且必须可见

只有策略配了 `fallbackModel`、且预算水位到阈值(默认 0.8),才会降级。
降级发生时三处都有痕迹,端到端测试逐一断言:

1. 响应头 `x-dshwar-model-downgraded` —— **用户有权知道自己被换了模型**
2. 会话记录用裁决后的模型 —— 计量与审计要对上真正在跑的模型
3. 审计 `model.downgraded`,before/after 都在 —— 「为什么答案变笨了」的唯一答案

静默换模型省下的每一分钱,都会在第一次工单里加倍还回去。

三条边界规则:

- 没配 `fallbackModel` → 超阈值也不降级(超限走 policy 的 429)
- 预算水位未知 → 不降级 —— 降级的依据必须是真数
- 降级目标配成清单外 → **拒绝**,不放行一个清单外的模型(先准入,后降级)

## 写入口在哪

`/v1/admin/policies` 只读。改准入清单是商务动作,该走控制平面(V0.5.0)的
审批流,不该是一个 curl 就能干的事。
