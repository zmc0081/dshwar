# @dshwar/fs-tenant

## 0.5.0

### Minor Changes

- 0b5fe40: 路径模型改为四段:`{root}/{tenantId}/{userId}/{workspaceId}`
  
  **这是一个有时限的改动。** `fs-tenant` 属于 V0.1.0,状态是「开发完成,待发布」——
  此刻改是普通改动,一旦发布出去就是破坏性变更,要升大版本、写迁移、维护双版本。
  
  - `workspaceId` 与 `tenantId` / `userId` **同级对待**:同一套白名单校验与
    SHA-256 编码,不因它来自请求而放松。
  - 校验顺序:**先逐段校验 → 拼接 → resolve → 断言仍在根内**。四步都要,
    不能用「拼接后再检查」替代「拼接前先校验」——一个叫 `..` 的 workspaceId
    会先把路径抬回用户根再被后续段落补回来,最终 `isWithin` 通过,
    但它落在了别人的目录下。
  - 缺省工作区 `default`(R2):未指定时落到它,现有调用方零改动仍能工作。
    **缺省只发生在取值阶段,不发生在校验阶段** —— 给缺省值开旁路,那条旁路
    就是攻击面。有测试证明非法 workspaceId 不会回落到 default。
  - 新增 `tenantUserRoot()`:工作区的上一层,只用于跨工作区的列举操作,
    文档写明不得拿它当读写根。
  - `TenantFileSystemConfig.workspaceOf` 留注入点。**工作区来源的决定权不在本包** ——
    它是 `/v1` 契约的问题(查询参数还是路径段),由 Session 1 的 R6 裁决。
  
  逃逸测试按新增路径段全量重写(95 条,+28):每一种绕过手法都在 workspaceId
  这一段上重验了一遍 —— 空/仅空白、`..` 与多级、正反斜杠、绝对路径与 UNC、
  8.3 短名与保留设备名、URL 编码、Unicode 规范化、伪造 `_h_` 前缀占位;
  外加**跨工作区隔离**的正反向断言与真实符号链接测试。
  
  符号链接测试在 Linux 容器复验(`pnpm test:linux`),确认真的执行而非静默跳过。
